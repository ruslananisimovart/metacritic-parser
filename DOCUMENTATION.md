# Документация

## Прогон

- Первый прогон дня (по поясу сервиса, по умолчанию Москва) берёт 20 игр из New Releases на https://www.metacritic.com/game/, следующие идут по списку SEE ALL с сортировкой "новые" и пропускают игры, обработанные сегодня. С новым днём выборка начинается заново.
- Данные берутся из внутреннего JSON API Metacritic, браузер не нужен. Игры попадают в каталог сразу по данным списка, подробности (разработчик, платформы, оценки игроков) догружаются следом.
- Число игр за прогон, расписание (каждый час, день, N дней, месяц) и пауза задаются в интерфейсе и хранятся в базе. Перезапуск для этого не нужен. После перезапуска сервис не повторяет уже отработанный слот.
- Резюме отзывов пересобирается, только когда число отзывов выросло больше порога (по умолчанию 10%).
- Обновление старых игр: сверх новинок прогон берёт игры каталога, которым пора по сроку (1, 3, 7, 14 или 30 дней), не больше заданного числа за прогон, самые давние первыми.
- Нет обложки, видео или описания на Metacritic: игра ищется в Steam (открытый API, совпадение названия и разработчика или издателя), затем в Google Play. Не нашлось: у свежих игр повтор через сутки, у остальных через неделю.

## Летсплеи

1. Поиск на YouTube по двум запросам, отсев правилами: длительность (по умолчанию 10-120 минут), название игры в заголовке, дата публикации.
2. Модель размечает кандидатов: летсплей это или обзор, трейлер, прохождение без голоса, ролик про другую игру.
3. Отобранные ролики проверяются по очереди, самые популярные первыми. Звук расшифровывает Whisper (large-v3-turbo) окнами, с таймкодами. Ролики длиннее 4 часов расшифровываются по началу и концовке.
4. Если речи блогера мало (меньше 100 символов на минуту), ролик отклоняется до модели и попытку не тратит. Остальные ролики того же канала пропускаются, проход берёт следующий летсплей, а когда найденные кончились, ищет новые.
5. Расшифровка режется на части по паузам (до 8 тыс. токенов для локальной модели, 15 тыс. для облачной), заключение строится по каждой части, пункты склеиваются, общий вывод пишется отдельным коротким запросом.
6. Каждый пункт "хвалит" и "ругает" привязан к месту в ролике: время берётся у сегмента, где нашлась цитата. Пункт без подтверждённой цитаты отбрасывается. Если блогер не высказывает мнения об игре, ролик отклоняется.

До модели за проход доходят не больше 3 роликов. Сбой (сеть, загрузка) повторяется через 30 минут, не больше 3 раз в сутки. Отказ YouTube попыткой не считается. "Летсплея нет" перепроверяется по правилу из интерфейса (по умолчанию раз в месяц, до 3 раз). Отклонённые ролики запоминаются и повторно не скачиваются.

Вход в YouTube: у сервиса свой профиль Chrome (`YOUTUBE_PROFILE`). В него один раз входят через пункт 4 лаунчера, дальше сервис сам экспортирует cookies для yt-dlp при старте, раз в 6 часов и при отказе YouTube. Аккаунт лучше отдельный. На сервере без экрана вместо окна входа кладётся готовый файл cookies (`YOUTUBE_COOKIES`).

## Модель

| `LLM_PROVIDER` | Что это | Ключ |
| --- | --- | --- |
| `kie` (по умолчанию) | агрегатор kie.ai, `gemini-3-8-flash` | `KIE_API_KEY_1`, запасной `KIE_API_KEY_2` |
| `google` | Gemini API напрямую, `gemini-3.8-flash` | `GEMINI_API_KEY_1`, `GEMINI_API_KEY_2` |
| `local` | LM Studio на этом ПК, `gemma-4-12b-it-qat` | не нужен |

Провайдер меняется в интерфейсе на лету, выбор хранится в базе. Ответы приходят строго по JSON Schema. Промпты собраны из общего ядра и добавок под облачную или локальную модель (`app/prompts.py`). Второй ключ включается, когда первый упёрся в квоту или кредиты.

Локальная модель и Whisper работают по очереди через общий замок видеокарты. Сервис держит в LM Studio одну модель с контекстом 32 тыс. токенов и выгружает её и Whisper после 2 минут простоя (`GPU_IDLE_SECONDS`). Закрытый LM Studio поднимается командой `lms server start`, когда нужна работа (в LM Studio должна быть включена служба Local LLM Service). Пока модель недоступна, игры сохраняются без резюме, резюме достроит следующий прогон.

## Интерфейс

- Каталог: поиск, платформы, фильтры по готовности данных (полный анализ, летсплей, резюме, оценки, видео, обложка, описание), сортировка, бесконечная прокрутка. Фильтры запоминаются до сброса.
- Карточка игры: оценки по платформам, описание, резюме с всплывающими источниками, видео (трейлеры Steam через hls.js), похожие игры, летсплей с таймкодами и расшифровкой.
- Мониторинг: прогон по этапам, воркеры, ошибки, история, модель, Whisper, видеокарта, процессор, память, диск, сеть. Запуск и остановка прогона, окно "Расписание и прогон", календарь прогонов.
- Данные: "Опустошить" сохраняет каталог итерацией в `data/storage/`, "Подгрузить" возвращает её (добавить или заменить), выгрузка CSV и ZIP.

Сборки нет: Preact и htm лежат в `app/web/assets/vendor`, шрифты локальные.

## Запуск и управление

```
pip install -r requirements.txt
cp .env.example .env
```

| Команда | Windows | Linux, macOS |
| --- | --- | --- |
| меню | `Metacritic_Parser.bat` | `sh metacritic_parser.sh` |
| запуск, перезапуск, остановка, состояние | `Metacritic_Parser.bat start` (`restart`, `stop`, `status`) | `sh metacritic_parser.sh start` (`restart`, `stop`, `status`) |

Сервис запускается в фоне и переживает закрытие окна или выход из SSH. Остановка штатная: текущий шаг доделывается, прогон помечается прерванным, дочерние процессы (yt-dlp, ffmpeg) снимаются. Порт задаёт `SERVICE_PORT` (по умолчанию 8000), адрес `SERVICE_HOST` (по умолчанию 127.0.0.1, для доступа снаружи 0.0.0.0). Без лаунчера: `python -m uvicorn app.main:app --port 8000`.

База `data/games.db`, логи `logs/`, хранилище и выгрузки в `data/` создаются сами при первом запуске. Whisper при первой расшифровке скачивает модель (около 1,6 ГБ).

## API

Полное описание с примерами: http://127.0.0.1:8000/docs.

| Запрос | Что делает |
| --- | --- |
| `GET /api/games` | каталог: `q`, `platform`, `sort`, `order`, `limit`, `offset`, `has` (фильтры через запятую) |
| `GET /api/games/{slug}` | карточка игры |
| `GET /api/platforms` | платформы с числом игр |
| `GET /api/status`, `GET /api/events` | снимок мониторинга и он же потоком SSE |
| `POST /api/runs`, `POST /api/runs/stop`, `GET /api/runs` | ручной запуск, остановка, история прогонов |
| `GET /api/schedule`, `PUT /api/schedule`, `POST /api/schedule/preview` | расписание, настройки прогона и летсплеев |
| `GET /api/calendar?year=&month=` | календарь: факт по дням и прогноз |
| `GET /api/llm`, `PUT /api/llm` | выбор провайдера и модели |
| `GET /api/storage`, `POST /api/storage/clear`, `POST /api/storage/restore` | хранилище итераций |
| `GET /api/export/{name}.csv`, `GET /api/export.zip` | выгрузка: `all`, `games`, `summaries`, `letsplays`, `runs` |
| `GET /api/health` | число игр, последний и следующий прогон |

CSV в UTF-8 с BOM, разделитель запятая, списки в ячейке через `; `. После каждого прогона файлы пишутся в `data/exports/latest`.

## Консольные команды

```
python -m app.cli run-once                               один прогон без веб-сервиса
python -m app.cli media --all                            добрать обложки, трейлеры и описания из магазинов
python -m app.cli summary valheim --kind critic --save   пересобрать резюме игры
python -m app.letsplay_cli game elden-ring               летсплей для игры из базы
python -m app.letsplay_cli conclusion valheim            пересобрать заключение по сохранённой расшифровке
```

## Ограничения

- API Metacritic неофициальный: при смене схемы разбор падает с понятной ошибкой и не пишет пустые данные.
- Видео от Metacritic есть примерно у 15% свежих игр, остальное добирается из Steam.
- Поиск на YouTube идёт без ключа API, по странице выдачи. С некоторых адресов YouTube требует вход, поэтому нужен профиль или файл cookies, а yt-dlp нужно держать свежим.
- Похожие игры ищутся внутри каталога, пока он маленький, их мало.
- Трейлеры Steam в интерфейсе играют через hls.js с cdnjs.
